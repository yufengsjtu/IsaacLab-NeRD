## Train the stock G1 teacher policy

`Isaac-Velocity-Flat-G1` is the upstream G1 flat locomotion task: stock
`g1_minimal` USD, analytical Newton physics, heading-tracking velocity
commands (`vx in (0, 1) m/s`), and the stock RSL-RL agent
(`max_iterations=1500`, `save_interval=50`, `experiment_name=g1_flat`).
Train this policy on the current Isaac Lab stack before running the formal
NeRD mix:

```bash
./isaaclab.sh train \
  --rl_library rsl_rl \
  --task Isaac-Velocity-Flat-G1 \
  --num_envs 4096 \
  --max_iterations 1500 \
  presets=newton_mjwarp
```

The run is written under `logs/rsl_rl/g1_flat/<run>/`. Copy the final
checkpoint, mix snapshots, and saved agent config into the paths consumed by
the formal presets (`save_interval=50`, so iterations 500, 1000, and 1499
are on disk):

```bash
mkdir -p pretrained/control_policy/g1_flat_terrain/params \
  pretrained/control_policy/g1_flat_terrain/checkpoint_mix
cp logs/rsl_rl/g1_flat/<run>/model_1499.pt \
  pretrained/control_policy/g1_flat_terrain/model_1499.pt
cp logs/rsl_rl/g1_flat/<run>/params/agent.yaml \
  pretrained/control_policy/g1_flat_terrain/params/agent.yaml
for it in 500 1000 1499; do
  cp logs/rsl_rl/g1_flat/<run>/model_${it}.pt \
    pretrained/control_policy/g1_flat_terrain/checkpoint_mix/model_${it}.pt
done
```

### Collision configuration compatibility

G1 NeRD resolves the stock task's default physics preset before copying its
collision pipeline and default shape settings. For the current stock G1
configuration, this preserves `margin=0.0` m, `ke=160000.0` N/m and
`kd=1100.0` N*s/m. NeRD still uses one neural solver substep per physics frame
and disables CUDA graphs; it does not inherit MJWarp's two solver substeps.

Earlier G1 NeRD configs read shape settings from the unresolved preset wrapper
and fell back to `margin=0.01` m instead. Recorded dataset contacts therefore
differed from the contacts reconstructed during NeRD rollout evaluation and
PPO. Re-evaluate existing dynamics checkpoints with the corrected defaults
before comparing rollout metrics or selecting a model. This fix does not
change the recorded datasets or checkpoint normalization statistics. Datasets
collected with custom shape settings still require matching runtime settings.

Policies trained under the previous NeRD defaults must be revalidated in both
the corrected NeRD environment and stock Newton/MJWarp. Retrain policies that
relied on the previous contact behavior; do not assume changing the evaluation
configuration alone repairs their behavior. The separate requirement to
regenerate old zero-`joint_f` datasets remains unchanged.

## Train an RL policy on flat G1 NeRD

Use a dynamics checkpoint trained on regenerated, nonzero `joint_f` data. Keep
this checkpoint fixed throughout the policy experiment. The G1 RL entrypoint
preserves the task's own rewards and contact-body selectors; it does not apply
ANYmal-specific MDP overrides. The G1 NeRD MDP uses geometry-based single-foot
support rewards, a geometry-contact sliding penalty, and torso-contact termination.
Force sensors remain disabled.
Its defaults are installed when constructing the task config. Runtime solver
overrides preserve subsequent reward weights, thresholds, body selectors, and
explicitly disabled terms instead of reinstalling those defaults.

`GeometryFeetAirTimePositiveBiped` matches the stock biped reward formula:
only single-foot support is rewarded, using the shorter current air/contact duration,
capped at 0.4 s and gated off for planar velocity commands at or below 0.1 m/s.
The inherited weight is 0.75 for flat terrain and 0.25 for rough terrain.
Air/contact timers update every physics step (5 ms by default), not only every
control step (20 ms). They use the solver's input-contact buffer, which precedes
the returned pose by one physics step. Geometry contact is not a contact-force
measurement; exact agreement with stock sensor timing is not guaranteed.

The flat NeRD task also enables `terminations.invalid_state`: root height above
1.5 m relative to the environment origin, absolute root linear velocity components
above 20 m/s, angular velocity components above 50 rad/s, or joint velocities above
100 rad/s terminate the episode as a failure. These are outlier guards, not physical
joint limits. Non-finite root or joint state raises `FloatingPointError` before
reward computation rather than allowing NaN rewards into PPO. The height guard is
not installed on the rough-terrain task.

Earlier policies used `GeometryFeetAirTime`, a touchdown-only reward with weight
0.25 and control-step timers. That implementation remains available for explicit
legacy ablations. Revalidate or retrain existing policies; changing evaluation
rewards alone does not repair their gait. Use identical invalid-state guards in
new/legacy training comparisons, and compare velocity tracking, support timing,
sliding proxies and non-timeout failures rather than raw returns across different
reward definitions.

Flat G1 NeRD defaults to the C reward configuration: single-support reward weight
**0.75** plus `GeometryFeetSlide` weight **-0.1**, inherited from stock G1 Flat.
The sliding term sums foot COM horizontal speed over bodies with geometric contact
in the last three physics steps, matching the stock history length and velocity
quantity but not its force threshold. It is a sliding proxy, not exact contact-point
slip. Rough G1 NeRD keeps its previous zero sliding weight.

This aligns reward formulas and weights, not the entire environment: NeRD uses
geometry contact instead of contact-force measurements, samples solver input contacts
one physics step before the returned pose, disables pushes, adds flat-terrain
invalid-state termination, and uses learned dynamics rather than MJWarp.

No sliding override is needed for new flat training. To explicitly reproduce the
single-support-only objective, append:

```text
env.rewards.feet_slide.weight=0.0
```

Existing checkpoints and experiment outputs are not changed. Default NeRD evaluation
now includes the sliding penalty as well, so raw returns differ from earlier
zero-sliding-weight evaluations; use the explicit zero-weight override when
reproducing those returns. Keep the dynamics checkpoint, seed, initialization,
PPO parameters and invalid-state limits fixed when comparing reward variants.

From the G1 worktree root, set `NERD_CHECKPOINT` to the dynamics checkpoint and
start with a short, headless PPO run:

```bash
export PYTHONPATH="$PWD/source/isaaclab_neural:$PWD/source/isaaclab:$PWD/source/isaaclab_tasks${PYTHONPATH:+:$PYTHONPATH}"
test -f "$NERD_CHECKPOINT"
uv run python -m isaaclab_neural.rl.rsl_rl.train \
  --task Isaac-Velocity-Flat-G1-NeRD-v0 \
  --neural-model-path "$NERD_CHECKPOINT" \
  --num_envs 64 \
  --max_iterations 5 \
  --seed 0 \
  --device cuda:0 \
  --run_name smoke
```

The NeRD task already selects its physics configuration. Do not pass
`presets=newton_mjwarp` or `--headless`; omitting `--viz` runs without a window.
Training uses `--num_envs` and `--max_iterations` (underscores), unlike the
NeRD evaluator's `--num-envs` and `--num-steps`.

This trains a new policy from scratch while keeping the dynamics model frozen.
`--neural-model-path` selects the dynamics checkpoint; `--checkpoint` is only
for a policy checkpoint used with `--resume`. Outputs are written under
`logs/rsl_rl/g1_flat_nerd/<timestamp>_smoke/`, including policy weights and
`params/agent.yaml`. After validating reset behavior, saved-policy playback,
and throughput, increase the environment count and training iterations.
Evaluate learned policies in stock Newton physics as well as NeRD to check
that improved rewards are not exploiting dynamics-model errors.

### Play the trained G1 NeRD policy

In the same shell, set `POLICY_CHECKPOINT` to the saved PPO checkpoint and keep
its adjacent `params/agent.yaml` when copying the run:

```bash
uv run python -m isaaclab_neural.rl.rsl_rl.play \
  --task Isaac-Velocity-Flat-G1-NeRD-v0 \
  --neural-model-path "$NERD_CHECKPOINT" \
  --checkpoint "$POLICY_CHECKPOINT" \
  --num_envs 16 \
  --num_steps 200 \
  --device cuda:0
```

Playback restores the saved runner configuration, including network structure,
action clipping, and seed, before constructing the policy runner. The playback
device replaces the saved training device; explicit `--clip-actions` and `--seed`
flags override their saved values. If `params/agent.yaml` is absent, playback
falls back to the task's registered agent configuration. Invalid saved YAML is
reported before simulation starts rather than silently falling back.

This restores the agent configuration only, not the saved environment or dynamics
configuration. Use the same dynamics checkpoint and repeat any environment
customizations used during training.

## Rough MBPO initialized from flat F_pre

`osmo_scripts/presets/g1_mbpo_rough.yaml` runs manager-based rough G1 with a flat
contact-token dynamics checkpoint. It does not require offline rough pretraining.
The policy is initialized from scratch with the rough task's height-scan observations;
a flat policy initialization checkpoint is not reused.

The workflow checks physical-state, H10 history, terrain origins, realized physical
parameters, manager/event clocks and clean observation restoration, including a controlled
stock push. A two-update coupled smoke must pass before the independent formal run starts.
The aligned preset uses 32 MJ worlds, 4096 NeRD worlds and 16 isolated fitting worlds.
Its runner is the resolved default `G1RoughPPORunnerCfg`: `[512,256,128]` actor/critic
networks and 3000 actual PPO updates, without selecting the separate 5000-update
`newton_mjwarp` agent preset. Model branches stay at 24 control steps (0.48 seconds).

At least 32 initial collection/model-warmup rounds are accounted separately. If the
first model is not ready, collection continues up to the declared 128-round warmup
cap, then waits with a bounded timeout. Warmup never consumes the 3000 PPO updates,
and insufficient data never silently reduces the evaluation sample count. The model
uses persistent Adam at `5e-5`, 256 updates per round, 64-update chunks, 128-row batches
and 32-row microbatches. The isolated rough collision model inherits stock collision
options and capacity rather than forcing legacy flat deterministic packing, whose
20-bit contact IDs cannot represent the default rough buffer capacity. Training
samples up to 512 accumulated iteration files; each validation batch has 256 held-out
windows from the latest 50 iterations. H10 real-MJ
truth and flat recipe replay have weights 0.5 each, and 16-physics-step real-action
loss has weight 0.5. The aligned preset retains the flat learner's Torch PD arithmetic
and frozen normalization. It does not run the old flat-retention gate on rough states.

Terrain geometry, difficulty range `[0,1]`, the 10-by-20 atlas, initial maximum level 5,
and real-MJ terrain curriculum come from the default G1 rough configuration. An explicit
shared terrain seed keeps all workers on identical geometry. The stock material, mass,
reset-force and push events are restored. Newton's material event uses its single
friction coefficient; it does not implement PhysX's separate dynamic-friction setting.
Real 20-second MJ episodes drive the default curriculum. Short imagined episodes do
not advance difficulty: ordinary NeRD resets sample real terrain/physical assignments,
and replayed branches restore their captured assignment and event timers.

Model holdout world IDs `[7,15,23,31]` span terrain columns and never enter model-fitting
batches. Model windows crossing reset or external state-jump boundaries are excluded;
real PPO transitions still include pushes. Captured parameters use an explicit
per-world protocol rather than claiming every randomized world has the mass of world 0.
The pretrained network still conditions on H10 state/effort/contact history, not explicit
mass/friction tokens; recording parameters does not by itself guarantee prediction accuracy.

Training uses geometry-contact versions of `feet_air_time`, `feet_slide` and torso-contact
termination, with the stock rough reward weights, including `feet_slide=-0.1`. It also
retains explicit learned-state numerical guards. Final deterministic MJ evaluation uses
new terrain seeds and the actual stock force-contact task, retaining contact sensors,
stock terminations and physical events. NeRD branch rewards and timeout bootstrap values
are logged separately; high model reward is not evidence of stock-MJ success.

Earlier fixed-atlas pilot runs remain reproducible from their frozen source/input snapshots.
The explicit `fixed` terrain, `nominal` physics-event and `nerd_legacy` runner profiles retain
the previous configuration paths; the registered NeRD rough task's legacy runner is unchanged.

Prepare locally with the existing flat checkpoint and audited recipe manifest:

```bash
uv run --no-sync python osmo_scripts/submit_mbpo.py prepare \
  --preset g1_mbpo_rough \
  --dynamics /absolute/path/to/flat_f_pre.pt \
  --reference-manifest /absolute/path/to/temporal_manifest.json \
  --output-dir logs/g1_mbpo_rough_submit
```

Preparation verifies the original recipe-source hashes, packages the current source
(including untracked source modules), and writes an immutable submission plan. It
does not upload anything. Review the plan's pool, resource/time limits, NV-Datasets
datasets and W&B entity before explicit submission:

```bash
uv run --no-sync python osmo_scripts/submit_mbpo.py submit \
  --prepared logs/g1_mbpo_rough_submit --confirm
```

The submitter reads `WANDB_API_KEY` from the environment and injects it through a
workflow-specific OSMO generic credential; no key is embedded in the preset or
workflow YAML. `prepare --wandb-credential NAME` reuses an existing generic credential
whose `api_key` entry is already configured, without changing its value. Set `WANDB_ENTITY` explicitly. The default W&B project is `rl`, the
group is `mbpo-g1-rough`, and separate metric namespaces report PPO, MJ collection,
online model fitting and held-out evaluation. Diagnostic logs are uploaded as a W&B
artifact. W&B checkpoint uploads require explicit `wandb.save_checkpoints: true` in the preset.

Storage uses NV-Datasets, like the repository's `start.sh` launchers; MBPO workflows declare
no OSMO URL inputs or outputs. `submit` requires `NGC_API_KEY` and `NVDATASET_TENANTID`, then
creates one new immutable input dataset, `IsaacLab-NeRD-MBPO-G1-Rough-<id>`, containing the
code archive, F_pre and flat recipe cache. Upload refuses to modify an existing dataset and
runs in an isolated `uv run --no-project` SDK environment pinned by
`osmo_scripts/nvdataset_requirements.in`. Inside the workflow, the existing OSMO
`nvdataset_cred` credential supplies `NGC_API_KEY`/`NVDATASET_TENANTID`. The task installs the
same pinned SDK into `/tmp/nvdataset-venv`, separate from the simulator environment,
downloads inputs and verifies all three SHA-256 digests before extracting code. Policy/model
checkpoints, raw rollout data and logs are uploaded on success or failure to
`IsaacLab-NeRD-Output/<workflow_id>/`.
Use `--smoke-only` during preparation to omit formal training and final evaluation.
Use this dedicated submitter rather than the supervised-dynamics `start.sh` launcher.
A submission-attempt marker prevents blind retries after ambiguous network failures.

  ``Isaac-Velocity-Flat-G1``（heading + ``vx in (0, 1)``）。

### Shared per-body 100% pool-perturb（对齐 jiex ``HumanoidG1JPC_policy_perturbed``）

训练只使用 20M 从 teacher 状态池出发的 100 帧、每步新 random action 的 perturb。
policy 先采 **20M** ``dataset_policy_pool.hdf5``（与 perturb 训练量相同，不进训练），
再从该池抽 perturb。eval 看干净 stock G1 walking（``dataset_valid.hdf5``）。

## Bounded OPD cold-start workers

`isaaclab_neural.generate.opd` 实现从零 policy 的初始快照、物理步采集、MJ oracle 和动力学一致性评估。
这是有界 P0/P1 工具，不是自动 PPO–OPD 协调器；不会更新 policy、自动接受候选或启动长训练。
各 worker 在独立进程中只使用一个物理后端。首版最多 16 个环境，关闭 CUDA graph，并显式使用
5 ms 物理步、20 ms 控制步。正式采集使用任务的 reset/command 分布，不使用视频展示的固定速度。

从当前 worktree 启动，避免导入另一个 worktree 的 NeRD 包：

```bash
export PYTHONPATH="$(uv run --no-sync python osmo_scripts/lib/local_isaaclab.py export-pythonpath --project-root "$PWD")"
DYNAMICS=/path/to/pretrained_dynamics.pt
OUT=logs/opd_cold_start

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage init --dynamics "$DYNAMICS" --output "$OUT/init" \
  --num-envs 4 --device cuda:0 --policy-seed 0

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage collect --backend mjwarp --dynamics "$DYNAMICS" \
  --policy-snapshot "$OUT/init/policy_init.pt" --output "$OUT/random_mj" \
  --num-envs 4 --steps 128 --seed 10 --split train --device cuda:0 \
  --verify-recording-frames 16

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage collect --backend nerd --dynamics "$DYNAMICS" \
  --policy-snapshot "$OUT/init/policy_init.pt" --output "$OUT/student_queries" \
  --num-envs 4 --steps 128 --seed 10 --split train --device cuda:0

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage oracle --dynamics "$DYNAMICS" --queries "$OUT/student_queries"/context_h*.hdf5 \
  --output "$OUT/student_labels" --num-envs 4 --horizon 10 --device cuda:0

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage evaluate --backend nerd --dynamics "$DYNAMICS" \
  --queries "$OUT/student_labels"/context_h*.hdf5 \
  --output "$OUT/baseline_dynamics" --num-envs 4 --device cuda:0
```

所有输出目录必须为新目录，不覆盖已有模型/数据。初始化 snapshot 保存随机 actor、critic、optimizer、
配置、RNG 和显式 `ppo_updates_completed=0` / `next_iteration=0`；不是 C-1000 continuation。
采集只接受此初始 snapshot，或者显式指定 `--reference-policy PATH --pool reference --backend mjwarp`。
后者可用于重新采集 teacher 参考集，不冒充缺失的原训练集。动作使用真实 stochastic actor 分布。

数据 seed 分工固定为 train 10–19、validation 20–22、test 30–32，已有诊断 seed 可使用
`--split diagnostic`。RL 初始化 seed 单独指定。先在新验证 seed 上重复采集/标注，不能把训练 query
的派生标签改名当验证集。

每个 shard 按真实历史长度分组。`opd_queries` 没有可训练标签；`counterfactual_context` 只在最后一帧
使用 MJ 标签。两种模式均被旧 trajectory loader 拒绝；native CSR 保留原始接触，训练时重建 tokens。
`ContextDataset` 使用有效监督 mask，`ContextBatchSampler` 按长度分桶，不填充不存在的历史。
初期历史不足 10 帧仍保留，部分 reset 的重复历史与实际 solver 语义一致。

采集器使用独立 reservoir RNG，长历史由 `--capacity-per-length` 限制，短历史各最多保留 16 个 query。
`--record-envs` 是记录环境的预算上限；此有界 worker 要求它不小于环境总数，以保留任一环境失效前的完整上下文。
`--verify-recording-frames` 检查回调不改变被监测的物理/控制/solver 接触缓冲区和 Torch RNG。
`--no-record` 可生成对照 control trace。非确定性后端的长期闭环轨迹可能自然分叉，不把整段 hash 相等
当作唯一的无副作用证明；同时检查单步自重放、RNG、状态不变性和模型输入历史复现。

Oracle 对记录的状态恢复 FK/求解器内部状态，使用相同 raw action、处理后目标及隐式 PD；shadow PD
仅用于首步核验，不再次叠加 feedforward。默认十步参考是 **连续推进 50 ms 并保持记录的目标**，不是
重放未来十步 PPO 动作，也不是闭环 policy 性能评估。报告包含一步/短时 SI 均值、P95、非有限计数和
踝关节框架位置误差；后者不是鞋底接触点误差。

### Dynamics fine-tuning

使用 `train/cfg/G1/opd_finetune.yaml`，在其 `algorithm.dataset.context_datasets` 中填写训练及独立验证
shard 列表（支持 glob）。参考集、随机探索和 oracle 数据都应进入训练清单；名单及实际采样量需存档。
跨阶段 replay 配额和在线 promotion 不在此有界 worker 中自动实现。

```bash
uv run --no-sync python -m isaaclab_neural.train.train \
  --task Isaac-Velocity-Flat-G1-NeRD-v0 \
  --cfg /path/to/resolved_opd_finetune.yaml \
  --checkpoint "$DYNAMICS" --checkpoint-mode finetune --data-dt 0.005 \
  --num-envs 4 --device cuda:0 --eval-interval 0 --logdir "$OUT/finetune"
```

`finetune` 要求 checkpoint 的 RMS/loss weights 完整且冻结，不允许 `--update-dataset-statistics`；
它保留架构和权重，重置 optimizer、epoch、scheduler 进度及 best metrics。缺统计时直接拒绝。
原训练 CLI 默认仍为 `resume`，不改变现有恢复语义。显式 `data_dt` 只覆盖训练转移时间，避免把
20 ms 控制步误当 5 ms 数据步。该最小 context 路径只支持单进程、无额外 contact-force head 的微调。

训练损失按每个窗口有效标签数归一化。未监督的历史不是 MJ 真值；不能把它们伪造为全序列 target。
独立运行上面的 oracle/evaluate 做物理单位评估，再判断是否保留候选；不能仅凭训练 loss 或 NeRD reward
自动接受模型。`--eval-interval 0` 关闭旧 trajectory rollout evaluator，不代替这里的 oracle 验证。

`python -m isaaclab_neural.eval.dynamics_consistency --stage checkpoint --baseline F_pre.pt
--candidate F_candidate.pt --expected-updates 100 --output checkpoint_audit.json` 可检查权重更新、冻结统计
及 optimizer 进度。`--stage gate` 改为接收 baseline/candidate 的 evaluate JSON，另提供事先固定的
`--gate-config` 和 `--kind current` 或 `reference`；拒绝候选时退出码为 1。门禁要求相同 query hashes
和 horizons，不允许换一份更容易的验证集来接受模型。候选及拒绝报告均保留，不自动切换 active dynamics。

### Explicit context sampling and accumulation

OPD 模板使用 `algorithm.dataset.context_sampling` 明确规定每次更新的有效 anchor 数量：

```yaml
context_sampling:
  source_counts: {reference: 128, current_mj: 64, student: 64}
  length_weights: {1: 1, 2: 1, 3: 1, 4: 1, 5: 1, 6: 1, 7: 1, 8: 1, 9: 1, 10: 36}
```

来源取自 shard 元数据，不从文件名推断：`pool=reference` 为 reference，其余 `source_kind=mjwarp`
为 current_mj、`source_kind=nerd` 为 student。配额必须为正整数且总和等于 `batch_size`。
长度权重归一化后，此例为 80% 十帧、20% 其余短历史；这是显式实验先验，不是实际访问频率估计。
缺少任一请求的来源/长度桶会报错，不静默重新分配配额。桶内有放回采样，重复曝光量会记录。

每个逻辑 batch 按实际长度拆成 microbatch，loss 乘以 `microbatch anchors / total anchors` 后累积梯度，
最后只执行一次 clipping 和 optimizer step。不会把短历史补齐为假历史，也不会把小桶的一次 backward
算成完整的 optimizer update。此审计路径要求 `num_data_workers=0`，避免预取导致未消费样本被计入统计。
训练输出 `sampling_audit_epochN.json`，包含累计标签曝光、重复次数、长度/来源分布及采样索引 hash。

可在训练前重建采样预算，或者重建旧配置的采样行为（不执行网络前向）：

```bash
uv run --no-sync python -m isaaclab_neural.data.opd \
  --audit-config /path/to/resolved_opd_finetune.yaml --seed 11 --updates 100 \
  --output /path/to/new_sampling_audit.json
```

未设置 `context_sampling` 的旧配置继续使用长度分桶、小尾 batch 的旧行为，便于复现。
因此 100 次旧更新不一定等于 100 次新更新的标签曝光预算；不能据此单独归因采样改动的收益。
学习率对照应使用相同数据 hashes、采样 seed/索引 hash、来源配额、更新次数、RMS 和验证协议，仅改变 LR。
审计中的 loss 系数不是实际梯度范数或方向贡献；历史 trainer validation loss 仍不代替独立物理单位验证。

### Learnability and input-sufficiency probes

`fit-probe` 区分固定小集拟合能力与跨 episode 泛化。它只接受真实 MJ 历史，固定同样数量的 train/validation
行，使用全 batch、现有表示、原 RMS/loss weights 和新 Adam，不混 reference；最多 1000 updates。
预处理后的输入缓存每次 forward 都复制，避免模型原地归一化造成重复归一化。诊断 checkpoint 不自动部署。

```bash
uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage fit-probe --backend nerd --dynamics "$DYNAMICS" \
  --queries "$OUT/random_mj/context_h10.hdf5" \
  --validation-query "$OUT/random_mj_validation/context_h10.hdf5" \
  --output "$OUT/random_fit_probe" --probe-samples 64 \
  --probe-updates 1000 --probe-lr 0.0001 --num-envs 4 --device cuda:0

uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage target-probe --backend mjwarp --dynamics "$DYNAMICS" \
  --queries "$OUT/random_mj/context_h10.hdf5" \
  --output "$OUT/random_target_probe" --num-envs 4 --device cuda:0
```

`target-probe` 从实际饱和状态中选择最多32个anchor，并单独增加8个构造饱和边界target测试（状态仍取自原数据）。
每个case执行相同初态的 A/A/B 三次单步：A/A测底噪，B只把一个饱和关节的target向更深饱和方向移动
0.25 rad。它要求实际初始 clipped PD 相同，比较下一步5 ms的 SI 差异是否超过绝对容差和十倍A/A底噪。
源码中的 `joint_f` 是 clipped shadow-PD，不应自动等同于隐式PD在整个步内的真实积分力矩。

结果包含 train/validation loss与SI曲线、低维标准化输入分布、饱和频率、接触数量变化代理和逐case误差。
“真实采集状态”不意味着B的target也自然出现过；case比例不是实际标签冲突发生率。
小集能记住也不证明表示完整；有限配对实验未发现差异也不能证明输入充分。
本工具不会改变生产网络输入、物理参数、已有数据或 RL policy。

### Diagnostic target conditioning

`condition-pairs`（MJWarp）把真实饱和状态的 A/B 干预保存成可训练 native-CSR contexts；A/B 共用旧模型
可见输入，只改变最后一帧 target 和对应 oracle label，并保留原 episode family，禁止跨 split 泄漏。
训练、验证分别使用各自的输入 shard；不使用人为构造的边界 target 作为这组训练数据。

`condition-fit`（MJWarp 场景载体，不推进解析物理）读取 `--conditioning-config` YAML：

```yaml
updates: 300
lr: 0.00001
seed: 11
batch_size: 256
sampling:
  source_counts: {reference: 128, current_mj: 64, student: 64}
  length_weights: {1: 1, 2: 1, 3: 1, 4: 1, 5: 1, 6: 1, 7: 1, 8: 1, 9: 1, 10: 36}
train: [path/to/train/context_h*.hdf5]
validation:
  held_out: [path/to/validation/context_h*.hdf5]
```

同一次调用运行 masked/enabled 两组。省略 `sampling` 时使用固定全 batch，适合配对小集诊断。
新增特征为处理后 `q_target - q` [rad]；旧 encoder 顺序、backbone 和 RMS 不变。
在 Transformer 输入投影后追加零初始化的 block-linear contribution，与追加37个输入列数学等价，
但保留旧矩阵乘法的尺寸，减少零扩展引起的浮点差异。屏蔽组在新特征归一化后置零；两组参数量一致。
新统计只用训练 contexts 计算并冻结。运行前检查与 F_pre 的初始预测等价，运行后保存旧统计检查和采样 hash。

诊断模型使用 `g1_target_conditioning_v1` 格式，**不支持普通 RL/play checkpoint 自动加载**。
`condition-score`（MJWarp）配合 `--conditioned-model` 和配对 `--queries`，报告不含target时的成对loss下限、
A/B关节速度差的预测误差。训练集小幅低于该下限，不等于独立状态上的消歧义已成功。

`condition-evaluate --backend nerd` 通过既有 NeRD 步进路径、相同 oracle shards 和 held-target 协议评估。
诊断进程临时绑定一个只记录 processed target 的 post-actuator callback，长度必须与实际 state history 匹配；
预加载历史取自 query。评估结束后清理 callback/缓存并恢复原模型。没有修改生产 solver、控制器或奖励。

所有 output 必须是新目录；不得直接将诊断模型升级为 active dynamics。输入存在信息混叠仅是存在性证据，
不能据此保证加入target必然提升泛化或通过原门禁。

### Bounded online PPO/OPD pilot

`online-arm` 在持续的8环境 NeRD 实例中运行最多3轮，每轮最多5个完整 PPO update。
它调用当前 RSL-RL 的 act/process_env_step/compute_returns/update 接口，不在 rollout/update 中途换动力学。
跨轮保留观测、policy optimizer、episode计数和真实state history；候选通过门槛后才更新下一块的模型权重。
当前实现要求关闭 CUDA graph、feature cache 和 KV cache，避免旧特征跨模型复用。

```bash
uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage online-arm --backend nerd --opd-mode online \
  --online-config "$PROTOCOL" --policy-snapshot "$INITIAL_POLICY" \
  --dynamics "$DYNAMICS" --output "$OUT/online" --num-envs 8 --seed 11 --device cuda:0
```

对照改为 `--opd-mode fixed` 和另一个全新 output。两组从同一随机actor/critic快照开始。
协议JSON必须预声明rounds、ppo_updates_per_round、env_seed、policy_rng_seed、sampler_seed、
dynamics_updates/lr、reference_train、initial_replay、reference_validation、reference_baseline_report和gate。
当前有界 worker 的 reference/current/replay 配额固定为128/64/64，使用H10；replay按历史阶段均衡。
记录器保留每轮最多256个H10 anchor，从真正的PPO rollouts抽样，不是用最终policy重新采一遍。
环境0–5用于动力学训练，6–7持续保留作当前分布验证；policy本身仍在全部8个环境中学习。

每个候选最多10次fresh-Adam更新，从当前已接受动力学开始；旧RMS/loss weights冻结。
MJ oracle、候选训练与验证在独立子进程运行，父训练环境暂停，不人为reset。
默认 `gate.reference_mode=enforce` 检查当前一步/十步均值和P95、实际改善，以及相对F_pre的累计reference保真；拒绝候选不改变活动模型。
独立研究协议可显式设置 `reference_mode=monitor`，只取消有限reference误差退化的一票否决：仍完整记录
`reference_vs_F_pre` 和 `strict_accepted`。当前分布门槛、相对F_pre的累计当前分布检查、空/非有限验证拒绝保持不变。
未知mode报错，省略mode仍为enforce。monitor仅用于隔离的任务适应实验，不代表模型通过原保真门禁，也不追认旧候选。
每轮保存查询、逐次PPO快照、命令、候选、gate报告及暂停前后状态/观测一致性检查。
普通完成的块边界可持续训练；该pilot不提供进程崩溃后的完整物理环境恢复。

`online-policy-eval --backend mjwarp` 对随机初始和最终policy进行独立seed的确定性策略评估。
报告xy/yaw跟踪误差、各终止原因、已完成episode长度及右删失长度；自动reset步不混入post-step跟踪误差。
`python -m isaaclab_neural.rl.rsl_rl.online_opd --summarize "$OUT"` 汇总协议、轮次和策略评估。
汇总区分候选接受数 `promotions` 和被后续PPO实际使用的次数 `promotions_used_by_ppo`；最后一块PPO结束后
接受的候选尚未参与策略训练。若没有任何候选被接受，必须报告有效动力学更新为0，不能把两组策略差异归因于在线适应。

RSL-RL构造器会原地消费嵌套config中的class_name等字段，故必须传deepcopy并保存未消费的配置。
对早期pilot快照，评估器仅在提供原始协议/初始快照时恢复缺失字段，拒绝覆盖不一致的已有设置；
输出单独的 `policy_with_recovered_config.pt`，不修改原快照、actor/critic或optimizer权重。

### PPO update diagnostics

`ppo-diagnose` 在固定NeRD和原MDP下支持8或128环境、最多10次PPO update，不采集oracle、不更新动力学。
先在完整rollout上重算分布/log-probability，检查首次optimizer step前的一致性；不通过则停止并保存报告。
检查仅支持当前的非循环、无observation normalization、无RND/symmetry配置，并用fork_rng保留CPU/CUDA随机状态。

```bash
uv run --no-sync python -m isaaclab_neural.generate.opd \
  --stage ppo-diagnose --backend nerd --dynamics "$DYNAMICS" \
  --policy-snapshot "$INITIAL_POLICY" --output "$OUT/ppo128" \
  --num-envs 128 --seed 11 --probe-updates 5 --device cuda:0
```

观察器通过临时batch-generator、forward/gradient及optimizer hooks记录原生RSL-RL更新，结束后移除hook。
不复制或修改RSL-RL optimizer、clip或KL调度逻辑；单测对照其梯度更新结果和RNG状态不变。
每个minibatch记录KL、clip fraction、action std、entropy、advantage、actor/critic裁剪前后梯度及实际LR。
`--ppo-initial-lr 0.0001` 只在此诊断入口显式覆盖初始policy LR，同步optimizer与保存配置，不修改默认runner配置。

**每次update结束时的LR不代表整个update的LR。** 自适应调度可以在minibatch间先升后降，再回到下限；
判断PPO更新是否受限需要看完整KL/clip/LR轨迹，不能只看终点标量。
128环境诊断能运行，不等于现有8环境在线OPD recorder已支持128环境；后者的采集解耦是独立工作。
这些短诊断不替代同MDP的MJWarp-only训练基线或长程、多seed的策略收益评估。

### Equal-data active-collection model fitting

`--stage active-fit --backend nerd --num-envs 4 --active_fit_config STUDY.json` supported a separate
single-step supervised comparison after collector training. Its `prepare` mode selected8192 unique H10 anchors
per arm with balanced per-collector-iteration quotas, audited recorded PD, and cached only nonlearned physical-input
preprocessing. It never cached trainable contact/network features for optimization. Root/leg/arm/hand loss contributions
and physical-unit errors were reported separately; aggregate normalized error alone could hide hand-dominated acquisition.

The bounded `fit` mode used fresh Adam, frozen checkpoint RMS/loss weights, LR1e-5 and4 complete epochs with
current256/reference256 logical batches and microbatch32:128 updates per arm. The same validated real-MJ H10 reference
replacement pool was reused; it was not claimed to be the original large offline corpus. Seed20 cohorts selected epochs;
seed22 cohorts were final diagnostics, including fixed actual-target4/16-step rollouts and separate short-prefix metrics.
This historical selector (`selection_protocol=legacy_policy_proxy`) required0.5% relative-score improvement and
at most5% loss regression for each reference-policy cohort. It did not measure adaptation on held-out collector data
or certify preservation of the original pretraining corpus; its results must not be described as a complete coverage test.

`OpdEpochConfig.stop_on_validation_gate` retained its default `True`. Setting it to `False` only allowed a fixed-budget
study to continue after finite quality rejection; rejected epochs remained ineligible for selection. Non-finite losses,
gradients and changed frozen statistics still aborted and rolled back. Selected model and Adam states were checked together.
No candidate was installed into the live environment, and no task policy was updated.

The recorded study was single-seed and diagnostic. A checkpoint selected by one-step loss was not a production promotion:
reference multi-step errors, data-group metrics and downstream MJ policy behavior still needed independent evaluation.

### Old-data retention and new-distribution adaptation

`--stage active-evaluate --backend nerd --num-envs 4 --active_fit_config STUDY.json` supports read-only
`prepare` and `evaluate` modes. It evaluates preserved epochs, including candidates rejected by the historical selector,
without optimizer updates or overwriting prior models/reports. All87 prediction coordinates remain in the evaluation loss.

The repaired development protocol uses unused collector-validation worlds768..895 for selection and896..1023 for audit,
with the same world partition across all five data sources. Training worlds0..767 are rejected. Complete worlds keep
all their episodes and overlapping H10 histories in one role. Every candidate is scored on the same selection columns;
provisionally selected candidates are then scored on the same audit columns. Own-cohort adaptation and common-cohort
comparison are reported separately, rather than comparing absolute losses on datasets of different difficulty.

The primary objective is lower new-validation loss subject to nonregression on explicitly identified old data.
A fixed rehearsal training pool is labelled a **proxy**, never an original-data holdout. Missing or incompatible
originals produce `formal_acceptance=null`, not an automatic pass. State/action dimensions and provenance must be
checked even when a local HDF5 filename matches the archived training configuration. Do not pad a23-joint/59-state file
to pretend it is a37-joint/87-state original. Visited-distribution improvement is not proof of support expansion when
the original coverage reference is unavailable.

For future fitting, explicit `selection_protocol=old_new_retention` uses `retention_selection` containing
`old_names`, `new_names`, `old_kind=original`, and numerical tolerances. A prepared validation manifest must tag these
cohorts as `old_original_validation` and `new_visited_distribution`; `heldout_validation_cohorts` must be disjoint.
The original-data condition cannot be replaced by a policy/rehearsal proxy. Historical configs retain their labelled
legacy selector for reproducibility. Four/sixteen-step and downstream-policy metrics remain separate deployment
checks, not substitutes for directly measuring old fitting/retention and new-data learning.

### Fresh pretraining-recipe retention evaluation

When historical files are unavailable, the `recipe_prepare` and `recipe_evaluate` modes of `active-evaluate` accept
fresh trajectory datasets with recorded recipe, policy, code and data hashes. `old_kind=resampled_recipe` explicitly
separates this evidence from both historical originals and the rehearsal training proxy. It never sets
`original_retention_verified`; no optimizer or live model is updated.

Reuse `parse_dataset_specs` and `build_dataset_args` from the preset runner rather than reimplementing a similar
collector. The mixed recipe uses clean/noisy/checkpoint/pool-perturbed source weights20/20/20/40, with the checkpoint
share equally split among500/1000/1499. The builder does not apply its top-level PD-randomization flag to policy or
pool-perturbed trajectories; env-reset random/zero validation retains its own PD randomization. Keep trajectory
lengths, action refresh, noise clipping and hand-holding semantics unchanged when reducing the collection budget.
Use independent seed groups and independently regenerated walking pools for selection and audit.

Recipe retention uses nonoverlapping H10 windows and the original `SequenceModelTrainer` loss: weighted one-step MSE
at all10 teacher-forced positions, not a10-step autoregressive rollout. Source losses are aggregated with archived
training weights. Last-anchor loss is also reported to match the active-data metric. The six original-style validation
sources remain separate diagnostics; they do not silently change the training-mixture retention objective.

A failed retention gate keeps F_pre, regardless of new-data improvement. `recipe_audit_prior` can additionally audit
candidates fixed by a preceding study, but is diagnostic-only and preserves the current selection file. Reusing the
new-distribution development audit does not turn it into a new blind test. Fresh recipe samples measure approximate
old-distribution retention, not memorization or preservation of every historical training sample.

### Matched-size recipe replay ablation

`active-evaluate` mode `replay_prepare` builds a replacement reference cache from a third, independent recipe
collection. It rejects evaluation-file hashes, reserved generation seeds and walking-pool dependencies outside the
new replay collection. Current-data and validation caches remain unchanged. Largest-remainder quotas retain the
original reference-row count; the realized source proportions and optimizer exposure counts must be reported.
The replay cache deliberately exposes only last-anchor targets, not all10 sequence labels, so replacing its
source distribution does not also change the training objective.

For a paired fitting comparison, preserve the current anchors, reference pool size, Adam initialization, sampling
schedule, LR, batch/microbatch sizes, gradient clipping, frozen scales and update budget. Reproduce the legacy
control before interpreting the replacement arm. The old fitting callback may be retained for numerical replication,
but its `selected.pt` must not substitute for the repaired old/new selection rule. `recipe_evaluate` can compute fresh
new-selection metrics when `new_selection_matrix` is omitted, and can audit predeclared `fixed_audit_candidates`
independently of retention-constrained checkpoint selection.

A matching model-state fingerprint does not imply every Adam moment is bitwise reproducible on CUDA. In particular,
`contact_set_encoder.other_body_embed.weight` backward accumulation can differ at FP32 reduction scale on identical
inputs. Diagnose any mismatch before continuing: preserve model/buffer exactness, isolate the affected parameter and
moment fields, and record a scoped numerical audit rather than silently weakening model or retention gates.

### Stagewise active-learning cycle

Run the bounded local coordinator with `uv run python -m isaaclab_neural.rl.rsl_rl.active_cycle --config CONFIG.json
--output NEW_OUTPUT`, using the current checkout's `isaaclab_neural` on `PYTHONPATH`. The config declares
`initial_dynamics`, `initial_policy`, `old_recipe_manifest`, `protected_recipe_collection`, `repository`,
`frozen_sources`, device, seeds and explicit collection/fitting budgets. The pilot accepts at most three stages,
32 collector PPO updates per stage and128 dynamics updates per stage at LR <=1e-5.

Each stage resumes the collector actor, critic and PPO optimizer, while creating fresh MJ worlds and H10 histories.
The `active-collect --active_resume` option preserves adaptive LR and cumulative policy iteration; without this flag,
the historical cold-start behavior is unchanged. A single NeRD checkpoint scores the entire PPO block. No model
switch occurs inside a rollout. The new data are on-policy for the MJ collector; this is not the separate
NeRD-autoregressive-rollout/oracle OPD workflow.

A `reference_command` argv template receives `{output}` and `{seed_offset}` and must generate an immutable
`collection_manifest.json` with `status=completed`, `training_updates=0`, frozen generator/policy `source_hashes`, and
`phases.replay` file entries. Entries retain dataset specs, actual commands, hashes and87/43/37 state/effort/action
widths. Walking pools must belong to that same collection. The standard mixed-preset dataset builder can serve as
the provider. Each stage uses an independent seed group; protected evaluation sources and previous reference
collections are rejected if their seeds or file hashes are reused.

The `active-stage-fit` worker consumes `dynamics_updates * batch_size` distinct old-reference H10 anchors without
replacement. The new half likewise consumes distinct selected rows, with `history_fraction` optionally retaining
past stages' training samples. Both coordinator and direct worker runs use0.5 mean full-history teacher-forced loss
for each half, with the exact pretraining weighted MSE operator, frozen coordinate weights/RMS, microbatch accumulation
and clip1. Current validation also uses all10 positions and retains last-anchor diagnostics. Validation is split by
complete held-out worlds into selection and audit; prior-stage selection worlds never become training replay.

Candidates must improve the current selection loss by `minimum_gain`, preserve every previous stage's new-selection
loss, and keep full teacher-forced old-recipe selection loss <=F_pre+1e-8. Only then does the coordinator switch the
next stage's scorer and continue the saved model/Adam pair. Rejected trials leave both model and optimizer at their
previous accepted state; a fresh Adam is used until the first candidate is accepted. Audit data are opened only
after candidate selection. Reports distinguish attempted model updates from accepted scorer changes, and rejection
can legitimately leave every stage scoring with F_pre. Global model defaults and prior artifacts are not changed.

### Full-history post-training contract and recorded-action diagnostics

`active_cycle` and `active-stage-fit` now share one fixed training/validation contract: both current and reference
data use all10 real teacher-forced positions and the pretrained loss operator. There is no anchor-only fitting branch.
The old `current_supervision`, `reference_supervision` and `current_validation_supervision` fields are deprecated
compatibility assertions: omit them, or keep `all_positions`. Likewise, `pretraining_loss` and the two
`retain_*_targets` fields may be omitted or set to `true`; incompatible values fail before loading models.
Historical anchor-ablation outputs remain separate research artifacts, not selectable modes of the current worker.

`active-stage-fit` accepts `prepare_only=true` to publish immutable full-label physical-input caches, exact
sample/window identities, validation entries and a batch trace without taking an optimizer step. Subsequent runs
can load the same `training_manifest` and its SHA256 rather than selecting another pool. With a fixed pool and seed,
reducing the executed update count consumes the same batch prefix; it does not reduce the prepared sample pool.
Use `expected_batch_trace_sha256` to enforce the expected schedule, including its prefix for a shorter verification run.

Each real input window `[s0,...,s9]` is supervised against the ten observed next states `[s1,...,s10]`.
This is shifted one-step teacher forcing at every position, not prediction of a disjoint future10-frame block.
Both halves average over samples, positions and coordinates before their0.5 mixture coefficients; enabling10 labels
does not multiply either half's coefficient by10. Both sources use
`MSELoss(prediction * loss_weights, target * loss_weights)`, matching the pretrained trainer's loss and gradients.

`reference_distillation_beta` optionally adds fixed-F_pre output preservation on reference training inputs only.
The objective is `0.5 * current_truth + 0.5 * reference_truth + beta * reference_keep`; the last coefficient is not
multiplied by0.5 again. `reference_keep` compares the student's full10-position prediction with the frozen
`initial_dynamics` teacher under the same coordinate weights. Current/historical-new inputs are never distilled,
and the real reference targets are retained unchanged. The teacher is constructed without advancing the training
RNG, stays in eval mode outside the optimizer, and is checked for unchanged weights/RMS and absent gradients.
At beta0 no teacher is constructed or evaluated. Nonzero runs separately log truth losses, raw/weighted keep loss,
and their total; calibrate the keep gradient after nonzero student drift, since it is zero at initialization.

Direct fixed-data studies can additionally set `reference_truth_weight` (default0.5), `feature_noise_std` (default0),
and independent `current_rollout_weight`/`reference_rollout_weight` (default0). Feature denoising perturbs only
`states_embedding` using a private RNG and frozen input-RMS scale, not physical states/forces/contacts or MJ labels.
The reference keep path always evaluates clean teacher and student inputs, including when the truth path is noisy.
A heavier reference coefficient is not renormalized with the unchanged current0.5 coefficient.

Nonzero rollout weights require a hashed `rollout_training_manifest` with distinct, complete, real-MJ training
records and explicit paired indices. Only `G1SequenceStudent`'s sequence term is added; its local-anchor term is
not added again. Zero weights skip rollout construction and backward computation. Scratch-world counts4/16 must
match the explicit `scratch_worlds` numerical profile for direct fitting/evaluation. The `active-loss-calibrate`
stage measures TF/keep/rollout gradient scales on declared training probes without optimizer updates; do not
assume that equally weighted new and old rollout losses have comparable gradients.

`reference_training_manifest` can reuse an immutable reference cache while preparing fresh current caches; the
parent and raw/cache hashes are checked instead of regenerating data under a changed collection implementation.
Set `defer_audit=true` for externally gated studies: fitting saves all checkpoints and reports **TF_PREFILTER_ONLY**,
without loading audit metrics. Apply preregistered multistep gates before locking candidates. Evaluation mode
`fixed_training_audit` requires a hashed selection lock listing the permitted final/diagnostic model hashes.
These direct-study options do not automatically change the active-cycle coordinator's acceptance policy.

Real-MJ context collection now records every post-step label and its physical frame/episode IDs. Full-supervision
readers reject missing full labels, frame gaps, reset crossings, non-MJ histories, anchor disagreement and broken
pre/post-state continuity. Old context files with placeholder intermediate `next_states` remain anchor-only;
they cannot silently become full-supervision data. Generic counterfactual NeRD contexts also remain anchor-only.
`--active_mode collect_train --split train` gathers new fully labelled training/validation worlds with a frozen
policy and zero PPO updates. `ContextDataset(..., supervision="all_positions")` explicitly selects verified labels.

Current, historical-current and reference fitting caches always retain complete H10 labels. Anchor-only caches
and mismatched last-position diagnostic targets are rejected. Their physical inputs remain immutable and can be
shared across verification runs. Report label-position exposures separately from unique windows.
The collector's curiosity reward still scores the warm last-position prediction; it is distinct from the fitting
loss. Pretraining's `eval_10-steps` joint-force-driven autoregressive metric is also distinct from this full-position
teacher-forced validation.

Set `check_every=1` and `record_step_zero=true` when inspecting the admissible update boundary. All steps, including
zero, are then saved, and the initial model is the explicit fallback if no trained candidate qualifies. Sparse
checks at steps1/4/8 do not establish that intermediate steps2/3 failed. Recipe metrics also report H1..H10 losses
so short-history repair can be distinguished from warm H10 retention.

`active-evaluate` mode `sequence_retention` compares frozen models on a hashed manifest of real-MJ sequence shards.
It replays their actual future target sequences, reports4/16-physics-step trajectory and endpoint errors, and adds
leg-velocity and FK ankle-frame position metrics with mean/P95/non-finite counts. Terminal and iteration-end
prefixes are reported separately rather than padded. This is distinct from holding one target throughout a rollout.
A teacher-forced retention pass is not sufficient evidence of preserved autoregressive dynamics or task-policy
performance.

The separate `active-joint-f-evaluate` stage reuses `TrainingRolloutEvaluator` for the pretrained joint-force-driven
10-step metric. Its hashed held-out trajectory file must not be an optimization source; all models share the same
sampled real warm-start windows. It permits up to64 scratch worlds and1024 rollouts, reports unweighted overall,
per-step and terminal state MSE, and advances only its isolated evaluation worlds with recorded forces rather than
recomputed PD. It does not perform optimizer/policy updates or modify checkpoints. Resampled files reproduce this
metric's semantics, not retention on unavailable original historical files.

### RL-stage coverage and training-sequence profiling

`active-collect --active_mode collect_benchmark --split validation --seed 60` collects evaluation-only data
from a saved stochastic policy in the stock MJ task, without the geometry reward replacement or hand-action
freezing. Seeds60..79 are reserved for this role. Stock observation corruption and contact sensors remain enabled;
keep the stock MJ determinism setting because run-to-run mode is incompatible with internal sensor computation.
Physics randomization remains disabled for this nominal-domain benchmark. Compare candidate models against the
same frozen observed trajectories rather than claiming that independently repeated MJ collections are bitwise equal.

`--active_random_init` is restricted to this benchmark mode. It builds an untrained actor using the checkpoint's
saved agent architecture, saves the actual new policy artifact, and separates its hash from the configuration
template. A saved RSL-RL `model_0.pt` can already contain the first PPO update: inspect optimizer steps rather than
calling the filename a random initialization. New evaluation episodes from existing teacher checkpoints do not
constitute a new independent policy-training run.

Frozen `collect_train` now writes `sequences_train.pt` and `sequences_validation.pt` alongside full-label contexts.
The permanent3:1 world partition applies to both formats. All future labels are observed pre-reset MJ states under
recorded four-control-step targets; terminal and iteration-end prefixes are retained, never padded. Real-MJ
collection also records optional raw `future_inputs`. `observed_sequence_rollouts` combines the actual warm history
and complete horizon-ended futures into a trajectory HDF5 for joint-force evaluation. It checks continuity and
label equality, and rejects NeRD-generated histories or missing future forces/contacts. These force-evaluation
files exclude terminal-ended windows; use the action-sequence audits to retain terminal-prefix diagnostics.

`active-evaluate` mode `rl_coverage` measures full-history TF and recorded-action rollout metrics on a hashed
benchmark manifest. The `active-sequence-profile` stage instead accepts only real-MJ **training** sequence shards;
benchmark/validation data are rejected before backward computation. It profiles logical batches64/256 at4/16
physics steps with4/8/16/32/64 scratch worlds, checks same-layout native forward parity and temporal gradients,
and verifies unchanged model/RMS/live state without optimizer steps. FK/collision refresh is still stop-gradient,
not a differentiable contact solver. Memory reports cover the Torch allocator, not all Warp/driver allocations;
record competing GPU workloads and distinguish logical batches from physical microbatch/world counts.

Sequence recording now copies only each tensor view's logical contents, rather than retaining the entire
multi-world backing storage in every history/future frame. This does not alter states, targets or replay
initialization. Older shards remain readable; `read_sequence_shard(..., memory_map=True)` can avoid eagerly
loading unused backing storage from immutable legacy files. Keep the mapped file unchanged while using
its tensors. Do not rewrite historical source files to change their recorded hashes.

`active_query_validity` provides non-mutating flat-G1 oracle eligibility checks: finite generalized states,
unit XYZW root quaternion, declared root-height bound, configured joint limits with explicit tolerance,
and maximum signed native-contact penetration. `joint_limit_tolerance_rad` is required: calibrate it on
real-backend controls, since soft limit enforcement can produce genuine small excursions, especially in
fingers. The masks are diagnostics, not proof of physical validity or a standing/task-success gate;
valid falling states can still be queried. Preserve rejected raw records and report exclusion counts rather
than clipping them into different states. Task-policy diagnostic sequences must retain their validation
split and evaluation-only provenance and must never be reused as collector training data.

`isaaclab_neural.generate.neural_collector.run_neural_collector` is a programmatic worker

## G1 29-DoF I-BFM box interaction

`isaaclab_neural.controllers.ibfm` runs the released I-BFM policy
([Roboparty/I-BFM-Code](https://github.com/Roboparty/I-BFM-Code), 166.56M-step checkpoint, CC BY-NC 4.0)
on `G1_29DOF_IBFM_CFG`. The actor is prompted with the spherical log map from the backward embedding of
`[state, privileged_state]` to the command latent, so both observations are required even though the actor itself
reads only `[state, last_action, history_actor]`. Quaternions are Isaac Lab `(x, y, z, w)`; the box observation uses
the I-BFM object reference frame, offset from the box geometry by `BOX_GEOM_POS`/`BOX_GEOM_QUAT` in the demo.

Export the weights once in the I-BFM `uv` environment (`ibfm/.venv`):

```python
from humanoidverse.agents.load_utils import load_model_from_checkpoint_dir
import torch
m = load_model_from_checkpoint_dir("tasks/common/checkpoint_ref/checkpoint", device="cpu", strict=False).eval()
keys = ["state", "privileged_state", "last_action", "history_actor"]
n = m._obs_normalizer._normalizers
stats = {k: {"mean": n[k]._normalizer.running_mean, "var": n[k]._normalizer.running_var} for k in keys}
torch.save({"actor": m._actor.state_dict(), "backward": m._backward_map.net.state_dict(), "normalizer": stats,
            "meta": {"obs_dims": {k: stats[k]["mean"].numel() for k in keys}, "z_dim": 256, "hidden_dim": 2048,
                     "hidden_layers": 6, "embedding_layers": 2, "backward_hidden_dim": 256, "norm_eps": 1e-5}},
           "ibfm_policy_isaaclab.pt")
```

Carry Box demo (approach, lift, transport, place; get-up after falls; the hand capsules of the I-BFM MJCF are added
to the wrist-yaw links because the asset without hands has none):

```bash
PYTHONPATH="$PWD/source/isaaclab_neural:$PWD/source/isaaclab" python -m isaaclab_neural.eval.ibfm_carry_demo \
  --policy ibfm_policy_isaaclab.pt \
  --latent-dir I-BFM-Code/ibfm/tasks/carry_box/latents --push-latent-dir I-BFM-Code/ibfm/tasks/push_box/latents \
  --num-envs 64 --distance-range 0.25 --yaw-range 0.6 --seconds 60 --out carry.json --record carry.npz
```

Success follows the I-BFM protocol (box within 0.2 m of the goal for 0.5 s within 60 s). With a 0.7 kg box on the
ground, the released phase controller succeeded in 9/9 MuJoCo runs but in 25% of 32 Newton MJWarp runs: after a
failed placement the robot often stalls with its hands on the box top. The demo defaults (wider placement window,
goal lookahead, softer near-goal turning, re-approach, and a 3 s lift timeout with the Push Box backoff latent)
raised Newton success to 84% (91%, 81% and 81% over three seeds of 64 starts with ±0.25 m distance and ±0.6 rad
yaw randomization), without falls.

  Dataset rollout eval 直接使用 HDF5 的 `joint_f`，不会被当前 actuator telemetry 覆盖。
- NeRD `newton_native` 下关闭 `contact_forces`；`feet_slide` 使用 geometry 接触历史惩罚，Flat 默认权重为 -0.1，Rough 保持为 0；
  `feet_air_time` 使用物理步频的双足单支撑奖励，`base_contact` 使用 geometry 判定
  （`.*_ankle_roll_link` / `torso_link`）。
- G1 PD randomization 按 actuator 的 nominal stiffness/damping 做相对缩放；
  OSMO preset 默认范围均为 `0.8–1.2`，每个 env 在一条 trajectory
  开始时采样一次并保持不变。对 G1 **env-reset** 的 zero-action / hold-pose
  数据也会做这组相对缩放（对应参考仓库的 varied-gain passive）。从策略状态池
  出发的 pool-perturb **不**随机 PD。
- G1 Dataset-Gen reset 在默认关节状态上叠加位置 `[-0.2, 0.2]` rad
  和速度 `[-0.1, 0.1]` rad/s 扰动，并在默认 base 高度上叠加
  `[-0.1, 0.1]` m；关节状态会裁剪到 articulation soft limits。
  这些 reset 扰动不作用于 stock teacher 的 policy 数据；policy-pool 扰动从
  策略状态写入仿真，不再走 Dataset-Gen reset。
- Dataset-Gen 的速度命令为独立 ``vx/vy/yaw``，每 1 s 重采；NeRD RL 任务与
  stock teacher 仍使用 G1Flat 命令范围。
